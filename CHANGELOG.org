1. Portable =-gnu= release binaries can now link a host shared library whose

* v0.28.0
** Fixes
1. Dependabot auto-merge lands in a single pass, fixing a deadlock that stalled
   every eligible bump.  The flow used to inject the changelog entry as a
   separate commit and wait for CI to re-run before merging, but that commit is
   pushed with the Actions token — which does not trigger workflows — so the
   second run never fired and the merge never happened.  It now composes the
   entry from the PR, inserts it, runs the same changelog-additions gate inline,
   and squash-merges in one run; nothing is skipped, because the changelog check
   the bump is exempt from is performed here while the build and test checks
   already passed on the unchanged code.  The ABI-compatibility gate, which was
   excluded for Dependabot on the same faulty premise, now runs on every bump —
   a non-breaking one merges, and a breaking one fails the gate, never becomes
   mergeable, and waits for a human.  Spawns pick this up through their =@main=
   reference to the reusable workflows.
* v0.27.0
** Fixes
1. Dependabot auto-merge recognizes the bot again.  =gh= began reporting the
   Dependabot author login as =app/dependabot= rather than =dependabot[bot]=,
   and the auto-merge gate's exact-string match skipped every Dependabot PR.
   The run still exited zero and reported success, so nothing merged on spawned
   projects while the workflow looked healthy.  The gate now keys on the bot
   flag plus either login spelling, tolerating both the old and the current =gh=
   output; it lives in the reusable workflow spawns reference at =main=, so it
   reaches the whole fleet without a sync.  The stale post-generation step
   telling users to enable GitHub's Allow auto-merge setting is dropped — the
   workflow merges directly and never used the =--auto= queue that setting gates
   — and the rationale is now documented.
* v0.26.0
** Fixes
1. Published release binaries now run on non-Nix hosts.  Every archive
   previously held only a dangling symlink into a build-host store path rather
   than the executable, and the Linux glibc binary — even once unpacked — could
   not start off the Nix store, because its ELF interpreter and library search
   path were store paths absent on any other machine.  Archiving now follows the
   symlink to embed the real binary, and the Linux =-gnu= artifact is built
   through zig against a fixed, low glibc floor so it carries the conventional
   filesystem loader path and runs on any mainstream distribution while still
   linking the host's shared libraries at runtime.  The store-locked native
   build stays available from the flake and the binary cache but is no longer
   published, and the static =-musl= variant is unchanged.  Spawned projects
   gain the portable variant automatically.

* v0.24.0
** Fixes
1. CI now installs Nix and caches the =/nix= store through
   =nixbuild/nix-quick-install-action= + =nix-community/cache-nix-action=
   instead of the deprecated Determinate Magic Nix Cache, whose free backend
   shut down in February 2025 and whose reverse-engineered revival throttled CI
   with =HTTP 418= crashes.  The installer-and-cache pair is factored into a
   =.github/actions/setup-nix= composite action shared across every workflow, so
   the store is cached in the GitHub Actions cache with no external service or
   signing key.  The heavy cross-compile jobs (release artifacts, the
   release-binaries matrix, the darwin cross fixture) run restore-only so their
   large =musl= / zig-cross-darwin closures do not evict the shared toolchain
   cache the light jobs depend on.

* v0.22.0
** Added
1. A build-only =cross-fixture= crate and a =Darwin cross fixture build= CI job
   now guard the macOS cross-compile against the two paths the template's own
   pure-Rust crates never exercise: a C-compiling dependency (=ring=, compiled
   by zig in crane's deps-only phase) and Apple framework linking
   (=CoreFoundation=, resolved against the SDK's =.tbd= stubs).  The fixture is
   never published or attached to a release; it exists so a regression in either
   darwin path fails the PR rather than surfacing only when a real consumer with
   those dependencies builds.
** Fixes
1. The macOS-cross release build now compiles C and assembly dependencies (a TLS
   stack's =ring=, say) through zig in every build phase, so a workspace with a
   =cc=-crate dependency cross-builds for darwin instead of failing.  Previously
   only the final =cargo zigbuild= link got the zig C toolchain; crane's shared
   deps-only phase runs a plain =cargo check=, and a build script compiling C
   there fell back to the host =gcc=, which rejects the Apple flags (=-arch=,
   =-mmacosx-version-min=) the =cc= crate emits for a =*-apple-darwin= target.
   =mkDarwinCrossPackages= now sets the =cc=-crate cross variables
   (=CC_<triple>= / =CXX_<triple>=) to =zig cc= wrappers, which every cargo
   phase honours.  Pure-Rust workspaces are unaffected.
* v0.21.0
** Fixes
1. The musl and macOS-cross release variants now receive the project's whole
   =commonArgs= (=buildInputs=, =nativeBuildInputs=, =env=, every crane knob),
   so a crate with a native dependency — alsa for =cpal=, say — builds for every
   target, not just the native one.  Previously =mkMuslPackages= and
   =mkDarwinCrossPackages= assembled their own args and dropped the caller's, so
   such a project failed the musl build (and a darwin build needing a
   non-framework native lib would have failed too), even though the native build
   linked the dependency fine.  =mkDarwinCrossPackages= now routes through
   crane's two-phase build (like =mkMuslPackages=) rather than a hand-rolled
   derivation, which is what lets the caller's full =commonArgs= reach the
   dependency-compile phase; the cross target-specifics (the zig linker, the SDK
   env) are overlaid on top, so the contract matches =mkRustPackages=: the
   caller owns the knobs.

* v0.19.0
** Added

* v0.17.0
** Added
1. Release runs now build distributable binaries for the crates that opt in.
   After a publish run tags a release, it dispatches a =release-binaries=
   workflow that builds each opted-in crate across the mainstream targets
   (=x86_64=/=aarch64= Linux with both glibc and static musl, =x86_64=/=aarch64=

   that ships no binaries dispatches the workflow and it does nothing.

   =workspaces.<crate>.release-binary= in =rust-template.json=, and whether (and
   where) it publishes via an explicit =publish= destination list in its
   =Cargo.toml= (=publish = ["crates-io"]= or =publish = []=), decoupling
   publication from privacy.  Three compliance checks keep the release-binaries
   workflow wiring honest.
3. CI now builds an emitted project end to end and runs the emission, formatter,
   and review-stop test scripts in a =template-tests= matrix, and the foundation
   pin checks are activated rather than dormant.
** Fixes

   rather than emitting a bare =thiserror::= path, so a spawned project's cli
   and server crates compile.  Those archetypes had never been built in CI; they

2. Compliance checks are now owner-agnostic, so a fork of the template passes
   them without a rename to the upstream owner.

* v0.15.0
** Added
1. The =treefmt= prettier formatter now also formats =*.json=, with
   =**/elm.json= excluded so the elm toolchain keeps managing its own manifest.

2. Compliance now verifies the =treefmt.toml= formatter wiring.  A new

   prettier, org-fmt — to its expected command, file-type =includes=, and (for
   prettier) =excludes=.  The checks assert presence rather than byte-equality,
   so a spawn may add its own formatters without tripping compliance.

   reviewer defers to =CONTRIBUTING.org= and =llms.org= as the authority rather
   than carrying its own checklist, and compliance now verifies the hook, the
   agent, and the =COMPLIANCE:= marker that wires them together.
